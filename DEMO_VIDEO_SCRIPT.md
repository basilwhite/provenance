# Provenance — D9.1 Demo Video Script (5 minutes)

**Corrected version.** The original version of this file used the wrong claim-hash preimage delimiter (a space) instead of the real one (a NUL byte, `\x00`) that `src/domain/claimHash.ts` actually uses — a latent bug in that file's own comment/intent, confirmed by hexdumping the source (byte offset 180 is a literal `0x00`, not `0x20`). The corrected claim1 hash below (`0xd3c4cede...`) matches the value already published in your own README, which came from an actual live run — that's independent confirmation this version is right. If you already tried the old version of this script against a live server, that's why /submit or /audit would have failed signature verification.

Every value below (pubkeys, signatures, claim hashes) is real — generated by faithfully re-running your `src/crypto/{keys,encoding,messages}.ts` and `src/domain/claimHash.ts` logic (same `@noble/curves`/`@noble/hashes` versions, and now the same NUL-byte delimiter) and self-checked with `ed25519.verify` before being written down here. A companion `demo-commands.sh` has the same commands in one runnable file with pause points.

Two claims from one submitter are used (not the single claim in the README) because the spec's `n < 5 → 0.5` neutral-prior rule (F4.1) means a single claim with 2 audits can't show a real score — you need `n >= 5` total audits on record before the Wilson formula does anything but return 0.5. This also means the "Score update" beat in D9.1's own DoD is only visible this way, so the second claim isn't padding — it's what the spec's threshold plus one overturn actually requires to happen on camera.

**Before recording:** `npm start` in one terminal (server on `localhost:3000`), a second terminal for curl/CLI, and your editor open to `src/scoring/wilson.ts` for the 5-second cutaway in beat 5\.

## If you have extra time: bonus slashing beat (not required by D9.1)

The spec slashes a submitter's stake once a claim gets **two** overturns within 7 days (F5.1) — the single overturn above only demonstrates the "audit overturn" step D9.1 asks for, not slashing. To also show a stake slash on camera you'd need one more independent overturn on the same `claim2` hash (a 6th audit) before checking a stake-info endpoint — that requires generating one more signed audit, which isn't included above to keep the core script inside 5 minutes. Skip this unless you have room to spare.

## About the FIELD\_DELIMITER bug

`src/domain/claimHash.ts` derives `claim_hash` by joining `claim_text`/`evidence_uri`/`timestamp` with `FIELD_DELIMITER`, which its own comment implies is a space but is actually a NUL byte (`\x00`) in the source. Both the TS server and the new PHP port now behave the same way (consistently), and a NUL byte is arguably a *better* delimiter than a space — it genuinely can't appear in normal claim text or a URL, whereas a space theoretically could. The only real issue is the misleading comment and the fact that no test caught the mismatch between stated and actual behavior. Worth a one-line comment fix in `src/domain/claimHash.ts` at some point (`/** NUL byte; can't appear in claim text or a URI. */`), but not worth a behavior change at this point — the README, this script, and the PHP port are all already anchored to the real (NUL) behavior.
